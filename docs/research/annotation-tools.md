# How the strongest annotation tools label "one class + spans" on short texts

Scope: how Prodigy, Label Studio, Argilla, doccano, INCEpTION, brat, Datasaur, LightTag, Labelbox (and Potato, Scale, Ellf where they matter) design the screen, the span gesture, the label model, save/advance, undo, queue and suggestions. The target workload is quet-web's: 150 short informal Vietnamese finance notes (3–8 whitespace tokens, often unaccented, e.g. `ve may bay vietjet tet 2tr9`, `Quang còn nợ mình 1tr`), each needing one type out of 8, a `target` span, a `value` span, and a record status (complete / uncertain / skipped) in one pass.

Conventions: every claim carries a link to the page or source file that owns it. `[INFERENCE]` marks my own reasoning. Tool behaviour was read from official docs and, where docs were silent, from the tool's open-source frontend code (linked by file). I did not run the tools.

**What I could not verify.** Scale's public docs describe a task API (`namedentityrecognition` task: labelers "highlight any text entity mentions that correspond to the specified labels") but no annotator UI ([Scale API reference](https://scale.com/docs/api-reference/generative-ai)); its annotators work in a managed workforce UI, so it is excluded from the UI comparison. LightTag's UI is known to me only through its paper. Datasaur's docs I read do not state what "save" means or whether it auto-advances.

## 1. Prodigy (Explosion)

**Design philosophy, in their words.** The web app focuses "on **one task at a time**, and reducing each annotation to **simple and intuitive decisions**" ([Web Application](https://prodi.gy/docs/api-web-app)). The 2017 post argues that a UI "that requires 3 different actions (highlight, select, click)" should be replaced by "one binary decision using the model's predictions" because "the more time, clicks and effort it requires to complete a task, the less efficient the result" ([Supervised learning is great — it's data collection that's broken](https://explosion.ai/blog/supervised-learning-data-collection)). The 2026 guide adds: automate token-boundary selection so "the selection doesn't have to be pixel-perfect", "minimize unnecessary clicking, dragging and choices", and keep "one concept at a time" ([Optimizing annotation workflows](https://explosion.ai/blog/optimizing-annotation-workflows)).

**Screen layout.** A single centred card; a sidebar holds project info, a progress widget, optional accept/reject/ignore stats and the 10 most recent decisions ([Statistics and progress](https://prodi.gy/docs/api-web-app#statistics)). Screenshots: [annotated layout (SVG)](https://prodi.gy/docs/web_app_details.svg), [progress](https://prodi.gy/docs/web_app_progress.jpg), [history](https://prodi.gy/docs/web_app_history.jpg); live demos on each docs page and at [demo.prodi.gy](https://demo.prodi.gy).

**Span selection.** `ner_manual` / `spans_manual` highlight on token boundaries from a tokenizer: "the selection can 'snap' to the token boundaries and doesn't require pixel-perfect highlighting. Even if you only select parts of a word, the word is still locked in … For single-token entities, you can even double-click on the word" ([NER docs](https://prodi.gy/docs/named-entity-recognition)). Hovering a span's label highlights its tokens; clicking the label removes the span ([Span categorization](https://prodi.gy/docs/span-categorization)). Character mode is an opt-in escape hatch (`--highlight-chars`, toggled with `c`) ([recipes](https://prodi.gy/docs/recipes#ner-manual), [shortcuts](https://prodi.gy/docs/api-web-app#shortcuts-spans)). Individual tokens can be `disabled` so they can never be part of a span ([ner_manual](https://prodi.gy/docs/api-interfaces#ner_manual)). Whether the selection is committed immediately or needs a click is a setting: `ner_manual_require_click` "Don't auto-add the selection as an entity and require an additional button click" — so the default is auto-add on release ([settings](https://prodi.gy/docs/api-interfaces#ner_manual-settings)).

**Label choice.** The label set is a row of keyboard-accessible buttons (`label_style: "list"`) or a dropdown; keys `1`–`9`/`0` pick label 1–10, `shift+num` 11–20, and `keymap_by_label` lets you bind a letter per label (`{"PERSON": "p"}`) ([shortcuts](https://prodi.gy/docs/api-web-app#actions), [custom label keys](https://prodi.gy/docs/api-web-app#actions-custom-labels)). So the model is **pre-select a label, then highlight**. [INFERENCE: the docs state the sequence only indirectly — "highlighting them and selecting the respective labels" ([recipes](https://prodi.gy/docs/recipes#ner-manual)) plus `ner_manual_require_click`; the active-label-then-drag behaviour is what the live demo does.]

**Several span labels + a document class.** `blocks` stacks interfaces on one card — Prodigy's own example is `[{"view_id": "ner_manual"}, {"view_id": "choice", "text": None}, {"view_id": "text_input"}]`, i.e. spans, then a class choice, then a comment box ([Custom interfaces › blocks](https://prodi.gy/docs/custom-interfaces#blocks), [blocks interface](https://prodi.gy/docs/api-interfaces#blocks)). One caveat: `blocks` can only hold one instance of each interface. `choice` supports `choice_style: "multiple"` and `choice_auto_accept` (selecting the single option submits) ([choice](https://prodi.gy/docs/api-interfaces#choice)). For exclusive `textcat.manual --exclusive` "the answer is submitted automatically when you make a selection" ([Text classification](https://prodi.gy/docs/text-classification#manual)). A `validate_answer` hook runs on every submit and can refuse invalid annotations ([custom recipes](https://prodi.gy/docs/custom-recipes#validate_answer)) — the exact mechanism quet-web's "enter is refused while a span is unmarked" rule re-implements.

**Accept/save.** `accept` (`a`), `reject` (`x`), `ignore` (`space`); the decision is stored under `"answer"` and the next card appears; tasks are posted back in batches, with manual save on `cmd/ctrl+s` ([web app](https://prodi.gy/docs/api-web-app)). Guidance on manual recipes: use `accept` for everything including "**examples with no entities** … just as important"; `ignore` = skip entirely (don't know / unrepresentative); `reject` is for broken data ([NER docs](https://prodi.gy/docs/named-entity-recognition)). So an empty accept is how Prodigy expresses "no span" — it does not distinguish "not yet marked" from "none".

**Undo / queue / progress.** `backspace` undoes the last decision; the last 10 decisions are listed in the sidebar and clicking one re-adds it to the front of the queue ([web app](https://prodi.gy/docs/api-web-app#statistics)). The stream can be infinite; progress is a count (and a model-based estimate in active-learning recipes) ([text classification](https://prodi.gy/docs/text-classification)). No jump-to-record by design.

**Suggestions.** `ner.correct` and patterns pre-highlight spans as ordinary editable spans; the annotator "only has to correct"; accept commits ([NER › manual with suggestions](https://prodi.gy/docs/named-entity-recognition#manual-model)). Binary `ner.teach` flips the model: show one proposed span, press accept/reject. Throughput benchmarks from Explosion (their data, not independent): 949 annotations in about 2.5 h with `ner.manual`+`ner.correct` (≈9.5 s each, derived) and 1735 in about 2 h with patterns (≈4 s each, derived) ([NER docs](https://prodi.gy/docs/named-entity-recognition)). Research Explosion cites: sorting labels by confidence instead of alphabetically "noticeably disrupted the humans' spatial memory", and needing a "view more" click made annotators slower than unassisted ([Desmond et al. 2021](https://arxiv.org/abs/2104.04122), summarised in [the guide](https://explosion.ai/blog/optimizing-annotation-workflows#research-ibm)).

**What it hides.** Everything except text, labels, four buttons. Navigation does not exist on the card (the stream is the navigation). Guidelines live behind `h` ([instructions](https://prodi.gy/docs/api-web-app#instructions)). No per-span status, no per-type constraints (the nearest tools are `disabled` tokens and `validate_answer`).

## 2. Label Studio (HumanSignal)

**Layout.** Config-driven. The NER template is a label bar above the text; the labelling screen has an Outliner (regions list) and a Details panel that can be collapsed or detached ([Labeling guide › Outliner](https://labelstud.io/guide/labeling#Outliner)). Screenshots: [NER template](https://labelstud.io/images/templates/named-entity-recognition.png), [settings panel](https://labelstud.io/images/lsf-settings.png), [Outliner and Details](https://labelstud.io/images/outliner-details-panels-view.png); try configs in the [Playground](https://labelstud.io/playground).

**Span selection.** Drag over text; `<Text granularity="word">` "make[s] sure that all highlighted spans … are complete words" ([NER template](https://labelstud.io/templates/named_entity)); `granularity` also accepts `symbol|sentence|paragraph` ([Text tag params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/text.md)). Offsets are characters, and "every space in the text sample is counted" ([Text tag](https://labelstud.io/tags/text)). Overlap requires hiding the earlier region or holding ctrl/cmd while dragging ([guide](https://labelstud.io/guide/labeling#Label-overlapping-regions)).

**Label choice.** Pre-select, then highlight: "1. Select the label … 2. Click the text … Your changes save automatically. 3. Click **Submit**" ([guide](https://labelstud.io/guide/labeling#Label-a-region-in-the-data)). Each `<Label>` has an auto-generated `hotkey` unless set, plus `selected` (pre-select), `maxUsages`, `hint`, `alias` ([Label params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/label.md)). A settings toggle keeps the label selected after creating a region ([guide › Customize](https://labelstud.io/guide/labeling#Customize-the-labeling-interface)). Changing a region's label: select the region, pick another label.

**Class + spans together.** Put `<Choices>` (task level) and `<Labels>` in the same config. `perRegion="true"` attaches choices to each span, and `<View visibleWhen="region-selected">` shows controls only when a region is selected ([NER template › per-region](https://labelstud.io/templates/named_entity)). `Choices` has `required`/`requiredMessage` and `visibleWhen` (`choice-selected`, `choice-unselected`) plus `whenChoiceValue` to condition UI on a chosen value ([Choices params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/choices.md)), and `layout: select|inline|vertical`. [INFERENCE: `visibleWhen="choice-selected"` + `whenChoiceValue` is the closest LS equivalent of quet's `null_for_types`.]

**Save / advance / undo.** `Submit` (`ctrl/cmd+enter`) stores the annotation and moves to the next task in the label stream; `Skip` is `ctrl+space` (mac `alt+enter`); `ctrl/cmd+z` undo, `ctrl+shift+z` redo; `backspace` deletes the selected region; `u` unselects; `alt+.` cycles regions ([keymap.json](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/keymap.json), [Skipping tasks](https://labelstud.io/guide/skip)). Clicking a task from the Data Manager does not auto-advance ([guide](https://labelstud.io/guide/labeling#Choose-which-tasks-to-label)). Drafts are saved automatically and shown in history ([guide › exiting](https://labelstud.io/guide/labeling#Exiting-a-labeling-flow)). Skipped tasks leave your queue; if everyone skips they stay incomplete ([skip](https://labelstud.io/guide/skip)). Hotkeys are user-customisable ([Hotkeys](https://labelstud.io/guide/hotkeys)).

**Suggestions.** Predictions are imported with a `predictions` key and are read-only; if "Show predictions to annotators in the Label Stream" is enabled "predictions will be automatically copied to newly created annotations" ([Predictions](https://labelstud.io/guide/predictions#Predictions-are-read-only)). The Outliner marks regions created by a model ([Outliner](https://labelstud.io/guide/labeling#Outliner)). With an ML backend, text spans from interactive pre-annotation "are automatically accepted" ([guide › ML-assisted](https://labelstud.io/guide/labeling#Perform-ML-assisted-labeling-with-interactive-preannotations)).

**Progress.** Data Manager grid + label stream; no on-card progress bar in the docs I read.

**What it shows too much of.** Outliner, Details, settings, regions list, relations, comments — all collapsible but on by default. [INFERENCE: this is the "kitchen sink" end of the spectrum.]

### 2a. Label Studio deep dive: what the code actually does (priority reference; the user likes this tool)

Everything below is from the editor source (`web/libs/editor/src`, develop branch) unless a docs link is given. I read the code; I did not run it.

**Labels + Choices in one task.** One config can hold a `<Choices>` block (the record class) and a `<Labels>` block (span labels) over the same `<Text>`; the control tags are independent, and their visual order is the order in the XML ([NER template](https://labelstud.io/templates/named_entity), [Choices](https://labelstud.io/tags/choices)). `Choices` takes `choice="single|single-radio|multiple"`, `layout="select|inline|vertical"`, `required`/`requiredMessage`, `randomize`, and each `<Choice>` takes `hotkey` and a hover `hint` ([Choices params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/choices.md), [Choice params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/choice.md)). A required `Choices` that is empty at Submit opens a modal and, for per-region choices, selects the offending region ([Required.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/mixins/Required.js)).

**Label-then-highlight is mandatory for text, and it is one-shot by default.**
- In `RichText/view.jsx` `onMouseUp`: `if (!states || states.length === 0 || ev.ctrlKey || ev.metaKey) return this._selectRegions(...)`. With **no label active, selecting text creates nothing** (it only selects existing regions); with ctrl/cmd held it also selects instead of creating. With a label active it creates a region carrying that label ([view.jsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/object/RichText/view.jsx)). This is the opposite failure mode to quet-web's "a drag always writes to the active field": LS refuses to guess.
- After the region is created the label is deselected unless the setting **"Keep label selected after creating a region"** (`continuousLabeling`) is on; its default is `false`. `selectAfterCreate` also defaults to `false` ([editorsettings.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/editorsettings.js)). So the stock flow per span is: label key, then select = 2 events, repeated for every span.
- `Label` `maxUsages` counts regions already carrying the label (`usedAlready`, `canBeUsed`), so `maxUsages="1"` gives a field-like one-use label ([Label.jsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/control/Label.jsx)). I did not verify what the button looks like once exhausted.

**Granularity.** The `Text` tag default is `granularity: "symbol"` (characters); `word`, `sentence`, `paragraph` are opt-in, and a `Label` can override it (`label?.granularity ?? item.granularity` in `onMouseUp`) ([model.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/object/RichText/model.js)). So **stock LS is character-level and drag-only**; the word-snapped feel the user probably saw needs `granularity="word"`. The code also remembers the active label for a double-click (`DBLCLICK_TIMEOUT = 450` ms, `DBLCLICK_RANGE = 5` px, `doubleClickSelection`), i.e. double-clicking a word with a label active is the single-token shortcut. [INFERENCE from the code; there is no dedicated doc for it.]

**Hotkeys.** Explicit `hotkey` on `Label`/`Choice` wins. Otherwise `Hotkey.makeComb()` hands out the first free key from `"1234567890qwetasdfgzxcvbyiopjklnm"` in **tree traversal order** ([Hotkey.ts](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/Hotkey.ts), [Annotation.js `setupHotKeys`](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/stores/Annotation/Annotation.js)). So in a Labels+Choices config the order of the XML silently decides who gets `1`–`8`. Hotkey hints on labels are on by default (`enableLabelTooltips: true`), hints on tools/actions are off (`enableTooltips: false`), and all labelling hotkeys can be switched off (`enableHotkeys`) ([editorsettings.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/editorsettings.js)). Global actions: submit `ctrl/cmd+enter`, skip `ctrl+space`, undo `ctrl/cmd+z`, redo `ctrl+shift+z`, delete region `backspace`, unselect `u` ([keymap.json](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/keymap.json)). Note that LS's key for the most frequent action is a two-key chord.

**Save model.** The bottom bar (`BottomBar/Controls.tsx`) shows **Submit** for a new annotation and **Update** once it has been sent (`isUpdate = … sentUserGenerate …`), with a dropdown for "Submit and Exit"/"Update and Exit", plus Skip/Unskip. The button is disabled when the `annotations:deny-empty` interface is on and there are no results, or when `hasIncompleteRegions` is true (tooltip "Complete all regions before submitting"; the source comment ties this gate to regions still being drawn) ([Controls.tsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/components/BottomBar/Controls.tsx)). In parallel there is a **draft**: `autosaveDelay: 5000` ms in the annotation store ([Annotation.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/stores/Annotation/Annotation.js)), and the docs tell annotators to "check to make sure their draft was saved in the history panel" ([guide](https://labelstud.io/guide/labeling#Exiting-a-labeling-flow)). Submit in the stream moves to the next task; the Update path does not behave like a new stream item. So LS has exactly three states a user must tell apart: unsaved edits → auto draft (invisible unless you open history) → submitted (button now says "Update"). [INFERENCE: this is the same "draft vs saved" ambiguity the user complains about in quet-web.]

**Region list and relations.** The Outliner lists regions, groups/sorts them, shows model-created regions, and hosts relation creation ([guide](https://labelstud.io/guide/labeling#Outliner), [relations](https://labelstud.io/guide/labeling#Add-relations-between-annotations)). For two spans of a fixed schema it is redundant. The embeddable editor takes an `interfaces` array that turns UI parts on or off one by one: `panel` (undo/redo/reset), `update`, `submit`, `skip`, `controls`, `infobar`, `topbar`, `instruction`, `side-column`, `annotations:*`, `predictions:*`, `auto-annotation` ([frontend reference](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/guide/frontend_reference.md)). So the "calm LS" the user liked is LS with most of that list off: text, a label row, a choices row, a bottom action bar.

**Offsets.** LS reports `start`/`end` as character positions in the rendered text and fixes surrogate pairs (`fixCodePointsInRange`) ([Text tag](https://labelstud.io/tags/text), [view.jsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/object/RichText/view.jsx)); whether that equals Unicode code points on NFC text for Vietnamese was not tested.

**A Label Studio config for quet's task (sketch, not run) and what it cannot say.**

  <Choices name="type" toName="note" choice="single-radio" layout="inline" required="true">
    <Choice value="expense" hotkey="1" hint="Money leaves the user, no repayment expected."/>
    <!-- … 7 more, hotkeys 2–8, one hint each … -->
  </Choices>
  <Labels name="span" toName="note">

**Where Label Studio's pattern holds up against the six complaints (evidence only; the screen audit is not available to me).**

| Complaint | What LS does | Verdict from the evidence |
|---|---|---|
| Too much on screen | Stock UI is crowded (Outliner, Details, top bar, settings); the `interfaces` list shows how far it can be stripped | **Contradicted for stock LS, supported for "LS minus panels".** Prodigy and Argilla's focus view reach the same calm layout. |
| Marking spans is fiddly | Label chip is the one visible active state; no label ⇒ no span (no silent overwrite); `maxUsages`; per-label hotkey. But stock = char-level drag, label deselects after every span (2 events per span) | **Supported** for visible active label + no-guess rule + per-label key; **contradicted** by the 6-vs-4 event count (see the action table) and by the char-level default. |
| Picking the type is slow | `Choices` with hotkeys, `hint` tooltips, inline/vertical layout; auto hotkeys follow XML order | **Supported** (visible digits, hover definitions), but explicit hotkeys are required; `randomize` exists to fight position bias and conflicts with the spatial-memory result in [Desmond et al.](https://arxiv.org/abs/2104.04122). |
| Unclear what is saved | Submit/Update button + 5 s invisible draft + history panel | **Contradicted:** LS has the same ambiguity. Prodigy's accept = saved and Argilla's Submit vs Draft are cleaner or at least labelled in the form. |
| Keyboard scheme confusing | Hints printed on labels; few global actions, but chords (`ctrl+enter`, `ctrl+space`) | **Partly supported:** printing the key on the control is the pattern to copy; the chord for the most frequent action is not (Prodigy `a`, Argilla `Enter`, Labelbox `E`). |
| Looks bad | Colour-coded label chips, highlight colour matches label, optional inline label names on the region | **Supported:** every tool in this file colours by label; LS's chip + same-colour highlight is the clearest example ([screenshot](https://labelstud.io/images/templates/named-entity-recognition.png)). |

## 3. Argilla (Hugging Face)

**Layout.** Responsive two-column: left = control panel (search/filter/sort) + record card(s); right = a **form** of questions to answer, then `Submit`, `Save as Draft`, `Discard`; collapsible guidelines and progress panels at the bottom ([Annotate](https://docs.argilla.io/latest/how_to_guides/annotate/)). Screenshots: [UI overview](https://docs.argilla.io/latest/assets/images/how_to_guides/annotate/ui_overview.png), [focus view](https://docs.argilla.io/latest/assets/images/how_to_guides/annotate/focus_view.png), [span question](https://docs.argilla.io/latest/assets/images/how_to_guides/dataset/span_question.png); [live demo](https://demo.argilla.io/sign-in?auth=ZGVtbzoxMjM0NTY3OA==).

**Class + spans on one record.** A dataset has several questions; `LabelQuestion` (single choice, round buttons), `MultiLabelQuestion`, `SpanQuestion(field=…, labels=…, allow_overlapping, visible_labels)` and others sit in one form ([Dataset settings](https://docs.argilla.io/latest/how_to_guides/dataset/)). Tab/↑/↓ move between questions. This is the closest off-the-shelf match to "type + 2 spans + status": one `LabelQuestion` plus spans — but a `SpanQuestion` is one label set on one field, so "target" and "value" are two labels of one question, not two slots. [INFERENCE]

**Span gesture.** Labels are buttons in the form; selecting a label and then selecting text in the field creates the span. Source: `EntityLabelSelection.component.vue` maps options to digits (`index + 1`), accepts multi-digit codes with a 300 ms timer, shows a search box when there are ≥15 labels (`OPTIONS_THRESHOLD_TO_ENABLE_SEARCH = 15`) and collapses beyond `visible_labels` ([source](https://github.com/argilla-io/argilla/blob/develop/argilla-frontend/components/features/annotation/container/questions/form/span/EntityLabelSelection.component.vue)). `span-selection.ts` completes the left/right edges to word boundaries unless `allowCharacter` is on; docs: hold `Shift` to "fit span to character selection" ([source](https://github.com/argilla-io/argilla/blob/develop/argilla-frontend/components/features/annotation/container/fields/span-annotation/components/span-selection.ts), [shortcuts](https://docs.argilla.io/latest/how_to_guides/annotate/#shortcuts)). The implementation needs the CSS Custom Highlight API (`CSS.highlights`), otherwise it shows "not supported" ([SpanComponent.vue](https://github.com/argilla-io/argilla/blob/develop/argilla-frontend/components/features/annotation/container/questions/form/span/SpanComponent.vue)). So: pre-select label, then select; edges snap to words.

**Save / advance.** `Enter` = Submit and the next record appears automatically; `Backspace` = Discard; `Cmd/Ctrl+S` = Save draft; ←/→ page; `Prev` shows the submitted response again ([Focus view](https://docs.argilla.io/latest/how_to_guides/annotate/#focus-view)). Drafts are partial answers, because unanswered required questions block Submit ("you will need to save as a draft when you are not providing responses to all required questions" — [bulk view note](https://docs.argilla.io/latest/how_to_guides/annotate/#bulk-view)). Records move between Pending / Draft / Submitted / Discarded views.

**Queue / progress.** Status tabs plus a personal progress panel (Pending, Draft, Submitted, Discarded counts) and a dataset progress bar ([progress](https://docs.argilla.io/latest/how_to_guides/annotate/#annotation-progress)). Their recommendation: use Focus view "if you have a large number of required questions or need a strong focus on the record content", Bulk view for speed with one question ([views](https://docs.argilla.io/latest/how_to_guides/annotate/#focus-view)).

**Suggestions.** Model predictions are pre-filled responses marked `✨`, with optional confidence scores; admins can sort suggested labels first. "If you agree … just click Submit" ([Suggestions](https://docs.argilla.io/latest/how_to_guides/annotate/#suggestions)). Filter/bulk by score threshold.

**Hides.** Almost nothing in the form; single-question datasets are explicitly "a smoother annotation experience" with digit shortcuts.

## 4. doccano

**Project types matter.** doccano has separate project types: sequence labeling, text classification, and **"intent detection and slot filling"**, which is class + spans on one card ([Vue page](https://github.com/doccano/doccano/blob/master/frontend/pages/projects/_id/intent-detection-and-slot-filling/index.vue); import format `{"text": …, "entities": [[0,26,"City"],…], "cats": ["flight"]}` in [example.jsonl](https://github.com/doccano/doccano/blob/master/backend/data_import/pipeline/examples/intent_detection/example.jsonl)). Images: [tutorial annotation screenshot](https://doccano.github.io/doccano/images/tutorial/annotation.png), [intent screen](https://github.com/doccano/doccano/blob/master/frontend/assets/images/tasks/intent_detection.png). Labels get a shortcut key and colour in the label editor ([tutorial](https://doccano.github.io/doccano/tutorial/)).

**Layout (from the IDSF page source).** Card: category chips (`LabelGroup`) at the top → divider → the text in `EntityEditor`; sidebar: progress card + metadata; a ten-button toolbar (review, filter, order, guideline, comment, auto-labeling, clear, shortcuts, pagination) above. Slot `v-shortkey` binds each category's `suffixKey` ([source](https://github.com/doccano/doccano/blob/master/frontend/pages/projects/_id/intent-detection-and-slot-filling/index.vue), [ToolbarLaptop.vue](https://github.com/doccano/doccano/blob/master/frontend/components/tasks/toolbar/ToolbarLaptop.vue)).

**Span gesture and label choice.** `EntityEditor.handleAddEvent`: after a drag, **if a label is pre-selected (`selectedLabel`) the span is created immediately; otherwise a popup menu opens at the pointer** with an autofocused autocomplete and a list of labels showing their shortcut chips ([EntityEditor.vue](https://github.com/doccano/doccano/blob/master/frontend/components/tasks/sequenceLabeling/EntityEditor.vue), [LabelingMenu.vue](https://github.com/doccano/doccano/blob/master/frontend/components/tasks/sequenceLabeling/LabelingMenu.vue)). The plain sequence-labeling page has sidebar label chips that set `selectedLabel`; the intent/slot page does **not** pass `selected-label`, so every span there is highlight → popup → pick. Right-click deletes a span; Esc cancels. No word snapping is configured (only a `grapheme-mode` prop). [INFERENCE: character-level by default.]

**Save / navigate.** `Enter` = "Confirm the data"; ←/→ previous/next; shift+←/→ first/last ([FormKeyboardShortcut.vue](https://github.com/doccano/doccano/blob/master/frontend/components/tasks/toolbar/forms/FormKeyboardShortcut.vue)). `confirm()` posts, re-fetches the current page and refreshes the progress card ([source](https://github.com/doccano/doccano/blob/master/frontend/pages/projects/_id/intent-detection-and-slot-filling/index.vue)) — it does not itself move to the next record (the code has no page+1 on confirm). No undo; "Clear" dialog removes labels. Progress card: Total / Complete + % bar ([AnnotationProgress.vue](https://github.com/doccano/doccano/blob/master/frontend/components/tasks/sidebar/AnnotationProgress.vue)).

**Suggestions.** A toolbar "auto labeling" toggle calls the backend for unconfirmed docs and loads the result as real annotations, with no distinct pending state ([source](https://github.com/doccano/doccano/blob/master/frontend/pages/projects/_id/intent-detection-and-slot-filling/index.vue)).

## 5. INCEpTION (and WebAnno)

**Layout / gesture.** Full editor with a left sidebar (annotation detail editor, recommenders, active learning). Create a span: "click with the mouse on the text and drag … When you release the mouse, the selected span is activated and highlighted in orange. The annotation detail editor … offer[s] a choice on which layer the annotation is to be created" ([User guide › Spans](https://inception-project.github.io/releases/39.2/docs/user-guide.html)). Default granularity for span layers "is to annotate one or more tokens … but you can adjust to character level or sentence level" per layer. Features (the label fields) are editable in the sidebar: radio / combobox / autocomplete depending on tagset size.

**Hotkeys.** "Key bindings can be used to quickly set feature values on the currently selected annotation … assign CTRL P to PER … when you create a Named Entity annotation and then press CTRL+P, the value would be set"; with key bindings the focus does **not** jump to the first feature editor (which would otherwise swallow keystrokes). Navigation: Home/End/PageUp/PageDown, Shift+PageDown next document; undo/redo `Ctrl+Z`/`Shift+Ctrl+Z` per document ([user guide](https://inception-project.github.io/releases/39.2/docs/user-guide.html)). So INCEpTION is **highlight → then press a key** (select first, label second).

**Save.** "Annotations are always immediately persisted"; "finished" is a separate lock toggled in the document frame, which makes the document curatable ([user guide](https://inception-project.github.io/releases/39.2/docs/user-guide.html)). Original paper: [Klie et al. 2018](https://aclanthology.org/C18-2002.pdf).

**Suggestions.** Recommender predictions are "grey bubbles. Predictions can be accepted by clicking once on them. In order to reject, use a double-click"; experimental explicit Accept/Reject buttons appear on hover. Active Learning sidebar: one suggestion at a time with Annotate / Reject / Skip, auto-jumping to the next; skipped ones are re-offered at the end ([user guide](https://inception-project.github.io/releases/39.2/docs/user-guide.html)).

**Hides.** Nothing; it is a power tool (layers, relations, chains, curation).

## 6. brat

Select by drag **or double-click a word**; multi-word via ctrl+double-click on the first word then shift+click on the last; empty span via shift+click ([manual](https://brat.nlplab.org/manual.html)). After selection a dialog asks for the type; `kb_shortcuts.conf` maps one character per type for use in the dialog, and the docs recommend them with the "Normal and Rapid annotation modes" ([configuration](https://brat.nlplab.org/configuration.html)). Editing = double-click the box. Dialog-based (highlight → pick), no auto-advance (document browser), no queue.

## 7. Datasaur

**Gesture / label.** "Use your pointer to select a word or a group of words … A list of label classes will appear. Select a label from the list." The first nine labels show hotkeys `1`–`9`; typing filters the list and the hotkeys follow the *filtered* order; Shift or an opt-in "multiple label selection" setting applies several labels to one span with an `Apply label` step ([Span based how-to](https://docs.datasaur.ai/data-studio-projects/lets-get-labeling/span-based.md), [Shortcuts](https://docs.datasaur.ai/advanced/shortcuts.md)). Project options: "limit selection to a span of 1 token", "spans should have at most one label", and default selection "token-level or character-level" ([Span based](https://docs.datasaur.ai/data-studio-projects/nlp-task-types/span-based.md)). Backspace/Delete removes the selected label.

**Class + spans.** Combine span + line + document labelling in one project: "To label a span, highlight the text and choose a label from the label box. To answer a line, right-click the line … To label a document, open the Document labeling extension and answer the questions" ([Span + Line + Document](https://docs.datasaur.ai/data-studio-projects/lets-get-labeling/span-based/span-+-line-+-document-labeling.md)) — the class lives in a separate extension panel.

**Queue.** `Go` menu: to next/previous unlabeled span, unlabeled line, file or conflict; `View` filters (lines without span labels; "Suggested labels" vs "Labels from labelers") ([how-to](https://docs.datasaur.ai/data-studio-projects/lets-get-labeling/span-based.md)). Help: `Ctrl/⌘+/` lists shortcuts. Suggestions come from ML-assisted labelling extensions and are filterable as a separate set ([ML-assisted labelling](https://docs.datasaur.ai/assisted-labeling/ml-assisted-labeling.md)).

## 8. LightTag

Paper-level only ([Perry, EMNLP 2021 demo](https://arxiv.org/abs/2109.02320)). Relevant design decisions:
- **Large taxonomies** use a searchable class field because "long lists slow down annotators and introduce an availability bias".
- **Unobtrusive pre-annotations**: "If a user must make an action for every pre-annotation, incorrect ones risk increasing the total number of actions". They are shown as coloured underlines; hovering offers accept/reject; a batch-accept button exists; "a near doubling of annotator throughput achieved when only 50% of pre-annotations are accepted" (author's vendor claim; unreplicated).
- **Annotators' needs**: express the annotation, "avoid errors such as mistakenly annotating trailing whitespace", maximise throughput.

## 9. Labelbox

Text editor: "Create an entity by clicking the desired starting character and dragging", with a **Word mode default** where you "hover over and annotate full words with one click"; `Shift+W`/`Shift+C` toggle word/character ([Text](https://docs.labelbox.com/horizon/guides/text-editor)). Classifications (radio/checklist/free text) can be global or nested under an entity. Hotkeys: "put your most-used features at the top of your ontology … dedicated tool hotkeys to label the first 9 objects"; `E` submit/save, `Q` skip, `Backspace` delete, `Esc` deselect, `Tab`/`Shift+Tab` next list item, `Cmd/Ctrl+Z` undo ([Hotkeys](https://docs.labelbox.com/horizon/guides/keyboard-shortcuts)). Model: select the feature (1–9) → click word → submit key.

## 10. Others

- **Potato** (Stanford/Michigan): configurable open-source tool offering "keypress shortcuts, keyword highlights, tooltips", and reporting faster labelling "especially for long documents and complex tasks" ([paper](https://arxiv.org/abs/2212.08620), [docs](https://potato-annotation.readthedocs.io/en/latest/)). Not span-focused; included because its productivity features are the same ones the other tools converge on.
- **Ellf** (Explosion, beta): an agentic layer over Prodigy; nothing new in span UI, but its Prodigy-recipe module uses `blocks` and a JS round trip for "annotate → pick" flows ([Ellf modules](https://beta.ellf.ai/docs/modules#prodigy)).
- **Pre-annotation effects (research).** On Czech dependency annotation, pre-parsed data took about 1.7× less time with quality "not hurt", and the paper states that "judgments of annotators are influenced by the output of automatic pre-annotation" (higher agreement) ([Mikulová et al. 2023](https://arxiv.org/html/2306.09307v1)). [INFERENCE: for a benchmark whose labels will measure a model, that influence is a feature for throughput and a risk for independence; quet-web's `show_proposals=false` default is consistent with this.]

## Which patterns minimise actions for 3–8-token texts with 1 class + 2 spans

Counting model (mine): one key press, click, drag release or popup pick = 1 event. Worked example: `Quang còn nợ mình 1tr` → `lend`, target `Quang`, value `1tr`.

| Pattern (tool exemplar) | Type | Target span | Value span | Save | Total events | Device switches [INFERENCE] | Notes |
|---|---|---|---|---|---|---|---|
| Active-slot, label implied (quet-web today; `marking a span auto-advances`) | 1 key | 1 click | 1 click | 1 key | **4** | key→mouse→key (2) | Needs a way to retarget slot (Tab) when the wrong slot is active |
| Pre-select label, then select (Prodigy, LS, Argilla, Labelbox) | 1 key | label key + click = 2 | 2 | 1 | **6** | 4 | Labels are interchangeable, so a key per span is extra when the two spans are different *fields* |
| Highlight, then pick from popup (doccano IDSF, brat, Datasaur) | 1 key | drag + pick = 2 | 2 | 1 | **6** | 4 (popup interrupts) | Popup after every drag = modal interruption |
| Binary accept of an exactly right proposal (Prodigy `ner.correct`, Argilla ✨, LightTag batch accept) | 0 | 0 | 0 | 1 | **1** | 0 | Each wrong field then costs about 2 (remove + re-mark) |
| Class-only auto-submit (Prodigy `textcat --exclusive`) | 1 (submits) | — | — | — | 1 | 0 | Cannot hold spans; ordering conflict |
| Keyboard-only token selection | 1 key | 1–2 keys | 1–2 keys | 1 | **4–6** | **0** | Not offered by any surveyed tool [INFERENCE]; unproven |

Findings that drive the recommendations:

1. For two *different* span fields, the cheapest design is fixed slots with auto-advance. Label choice per span is wasted when each field has exactly one label; every surveyed tool models spans as a *label palette* because their span labels are a repeating set (many PERSONs), not a fixed slot. [INFERENCE]
2. Word-level snapping is the universal default for speed (Prodigy, Label Studio `granularity`, Argilla, Labelbox, Datasaur, INCEpTION), always with a character escape hatch.
3. Single-token spans are one click or double-click in Prodigy, brat, Labelbox; no drag is needed. In the sample queue most `value`s ("2tr9", "420k", "215.000", "1tr") and many `target`s ("Quang", "Fahasa") are single whitespace tokens. [INFERENCE from review-queue.jsonl]
4. Popups that appear after the gesture (doccano, brat, Datasaur) add a step, but they remove the "wrong active label" error class. Active-slot designs trade that for the hint/row mismatch quet-web's contract already documents.
5. Progress and navigation: tools built for flow (Prodigy, Argilla, Label Studio's stream) put nothing but progress on screen; tools built for management (Datasaur, doccano, INCEpTION) put pagination, filters, jump menus on screen.

## Implications for quet-web

Ranked by impact on the six complaints the user confirmed: **(A)** too much on screen, **(B)** marking spans is fiddly (drag/click, which field gets the selection, Tab between target/value), **(C)** picking the type is slow (8 long definitions in a side panel, keys hard to remember), **(D)** unclear what is saved (draft vs saved, what Enter does, when it advances), **(E)** confusing keys (`x n c m tab [ ] z \`…), **(F)** looks bad. Each item says what it fixes and takes a stance on the **Label Studio pattern** (the user's reference): *Adopt*, *Adapt* or *Reject*, with the evidence. I have not seen the screen audit, so "supported/contradicted" here means by the tool research only.

1. **Fix (B): copy Label Studio's visible active label + per-label key + one-use rule, but drop its deselect-after-every-span. — Adapt.**
   - Show the two span fields as two coloured chips above the text (`target`, `value`), each printing its own key (`t`, `v`); the active chip is the only lit one; a filled chip shows its text and an `×`. This is LS's `Labels` row with `hotkey` and `maxUsages="1"` ([Label.jsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/control/Label.jsx)), which answers "which field does my selection go to" by making it visible and addressable by one key instead of `Tab` cycling.
   - Keep the no-guess rule: LS creates nothing when no label is active ([view.jsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/object/RichText/view.jsx)). In quet-web a marked field should become inactive and the next unmarked field should light up automatically (what the contract already does), so a drag never silently overwrites a filled field; overwriting needs the field's own key or a click on its chip.
   - Do **not** copy LS's default of deselecting the label after each region (`continuousLabeling: false`, [editorsettings.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/editorsettings.js)): it makes 6 events for the sample record instead of 4 (action table), and Prodigy's whole argument is to cut that cost ([post](https://explosion.ai/blog/supervised-learning-data-collection)).
2. **Fix (B): one click = one whitespace token; word snapping as the default. — Adopt LS's `granularity="word"`, reject LS's default.** LS's default is `symbol` ([model.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/tags/object/RichText/model.js)), so stock LS makes you drag to hit characters. Prodigy (snap, double-click one token), Labelbox (word mode default, one click), brat (double-click word, shift-click range), Argilla (word completion, `Shift` = characters) all default to words. For these notes, `2tr9`, `215.000`, `420k`, `1tr` and most names are one token, so a single click is the usual gesture; drag or shift+click for multi-word targets such as `highlands coffee`; keep character mode behind one toggle. [INFERENCE: trim trailing `.,;:!?` on a click unless inside a number; check on the 150 queue records.]
3. **Fix (D): one save model, printed on the button. — Adapt LS's bottom action bar, reject its Submit/Update + hidden draft.**
   - Put three labelled buttons in a fixed footer bar like LS's `Controls`: **Complete ⏎**, **Unsure u**, **Skip s** (the three record statuses), each showing its key. Enter always means "save as complete and go to the next unlabelled record"; there is no draft state a user can see. LS's chord (`ctrl+enter`) is the thing to avoid: Prodigy `a`, Argilla `Enter`, Labelbox `E` are single keys.
   - LS's own ambiguity (button flips Submit→Update, 5 s autosave draft, "check the history panel" — [Controls.tsx](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/components/BottomBar/Controls.tsx), [guide](https://labelstud.io/guide/labeling#Exiting-a-labeling-flow)) is the cautionary example. Show one persistent status chip beside the record id: `Not saved` (any change since load), `Saved ✓ complete|uncertain|skipped`. When a gate refuses Enter, say why in the footer (LS: "Complete all regions before submitting"; Prodigy `validate_answer`: [docs](https://prodi.gy/docs/custom-recipes#validate_answer)) and highlight the offending chip.
   - Add a slim "last saved" strip (previous 3 records as chips; click to reopen) so `z` has an anchor, modelled on Prodigy's editable history ([history](https://prodi.gy/docs/api-web-app#statistics)).
4. **Fix (C): all 8 types as one row of numbered buttons with a one-line gloss; the long definition on hover/focus and on `?`. — Adopt LS `Choices` + `hint`.** LS shows `Choices` inline with a hotkey on each and a hover `hint` ([Choice params](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/choice.md)); that is the pattern for the schema's long definitions: gloss on the button (≈4–6 words, from the first clause of each definition), full text in the hover/focus card, not a permanent side panel. Constraints from the evidence: set `1`–`8` **explicitly** in schema order (LS's auto-assignment follows config order and then letters, so Labels placed first would take `1`/`2` — [Hotkey.ts](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/Hotkey.ts)); keep a fixed order and do not reorder by proposals (sorting by confidence "noticeably disrupted" spatial memory — [Desmond et al.](https://arxiv.org/abs/2104.04122)); LS's `randomize` (position-bias control, [Choices](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/includes/tags/choices.md)) is the opposite trade-off and would slow learning of the keys — Reject for this workload [INFERENCE]. 8 labels is under Prodigy's 10–20 threshold for splitting a scheme ([docs](https://prodi.gy/docs/text-classification#large-label-sets)); search only above 15 (Argilla's cutoff).
5. **Fix (E): cut the keyboard scheme to what is printed on a control. — Adopt LS's "hint on the control" idea; reject the long tail.** LS prints hotkeys on labels by default (`enableLabelTooltips: true`) and has a short list of global actions ([keymap.json](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/settings/keymap.json)). Target set, every key visible on its button: `1`–`8` type; `t`/`v` (or `Tab`) span field; `n` none for the active field; `Enter`/`u`/`s` save; `z` undo; `←`/`→` previous/next; `?` help. Demote `x` (select with keys), `c` (span status), `m` (snap), `[`, `]`, `\` to menus or the help sheet; `c` becomes a click on the filled chip, `[`/`]` fold into the single behaviour of `Enter`/`→`. Rule: a key that is not printed on a visible control does not exist in the basic scheme (Argilla shows keys in its buttons — [shortcuts](https://docs.argilla.io/latest/how_to_guides/annotate/#shortcuts); Datasaur shows the first nine in the label box — [shortcuts](https://docs.datasaur.ai/advanced/shortcuts.md); Labelbox maps hotkeys to ontology order — [hotkeys](https://docs.labelbox.com/horizon/guides/keyboard-shortcuts)).
6. **Fix (A): three bands and nothing else. — Adopt the calm LS layout (text + label row + choices row + bottom bar), reject stock LS.** Header: record id, `27 / 150` with a thin bar, queue button, help. Centre: slot chips, the note in large type, type row. Footer: status buttons and the saved chip. Remove the side palette, the previous/next/unlabelled buttons and the span tool row from the card (save already advances; navigation stays on keys and the queue drawer). LS shows this is reachable by switching `interfaces` off item by item ([frontend reference](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/guide/frontend_reference.md)); Prodigy's card has no navigation at all; Argilla recommends focus view for form-heavy tasks ([views](https://docs.argilla.io/latest/how_to_guides/annotate/#focus-view)). The Outliner/region list adds nothing for two spans: **Reject** it.
7. **Keep and surface quet-web's "none vs not marked" separation, and make n/a automatic. — Beyond LS (it cannot say this).** In the tools I read, "no span" is an empty annotation (Prodigy says so explicitly — [NER docs](https://prodi.gy/docs/named-entity-recognition); LS has no per-span none either). quet-web's explicit `none` plus the Enter gate is a real advantage: show unmarked slots as an empty, emphasised chip and explicit none as a muted "none" chip. When the chosen type is in a field's `null_for_types` (e.g. `transfer` → target), set that field to `none (n/a for transfer)` and skip it in auto-advance so `Enter` works after the value alone. Per-type constraints have only weak precedent elsewhere (Prodigy `disabled` tokens, `validate_answer`; LS `visibleWhen` on `Choices`).
8. **Fix (F): colour per slot, restrained, one type scale. — Adopt LS's chip-plus-matching-highlight.** Two slot colours that match chip and highlight ([LS screenshot](https://labelstud.io/images/templates/named-entity-recognition.png)), the type row in a neutral outline with the selected button filled, status buttons with a single accent for the primary action. Large note text (the contract's 36px serif is a fair choice for 3–8 words), generous spacing; no accent colour beyond the two slot colours and one primary-action colour. [INFERENCE: visual polish is outside what the tools' docs measure.]
9. **Proposals: keep off by default; when on, overlay them on the real text and accept per field. — Adapt.** Pre-annotation speeds work (≈1.7× in [Mikulová et al.](https://arxiv.org/html/2306.09307v1)) yet "influences" judgments, which matters for a benchmark. When enabled follow LightTag/INCEpTION (marks on the text, one click to accept) and Argilla (prefilled with a ✨ marker, `Enter` accepts): dashed marks on the proposed tokens, a ✨ chip on the proposed type, `p` accepts all, a click on a dashed mark accepts that field. LS copies predictions into the annotation as ordinary regions when enabled ([predictions](https://labelstud.io/guide/predictions#Predictions-are-read-only)); that loses the "not accepted" state quet-web wants.
10. **Experiment later: keyboard-only span selection.** Tiny home-row badges on tokens (`a s d f …`) would make a record fully typeable (`3` `d` `f` `Enter`). No surveyed tool does it [INFERENCE]; test against the 150 notes with a stopwatch before building.

**Embed Label Studio instead of rebuilding?** The editor is an embeddable library with the `interfaces` switches above ([frontend reference](https://raw.githubusercontent.com/HumanSignal/label-studio/develop/docs/source/guide/frontend_reference.md)), but I found no way to express items 3, 4, 5 and 7 (single-key Enter, gloss plus hover definitions, explicit none, `null_for_types`) without custom code, and quet-web's CSP (`default-src 'self'`, see [contract](../contract.md)) and framework-free esbuild setup make a large third-party bundle a heavy bet. Not verified beyond that; the recommendation is to copy the pattern, not the code. [INFERENCE]

### Addendum: per-span status and a required note for "unsure" (from Main, after a gidi validator test)

Requirement: span status `sure/unsure` on slots that declare statuses (toggle, key `c` on the active slot), and a one-line "What is unclear?" note that auto-focuses on `u` or on any unsure span, is required for those saves, shows on revisit, and is otherwise absent. What the tools say about the pieces:

- **Per-span attribute next to the span, not in a side form.** Label Studio's own recipe for this is `perRegion="true"` controls shown only when a region is selected — its NER template adds a per-span `Rating` for "your confidence" inside `<View visibleWhen="region-selected">` ([template](https://labelstud.io/templates/named_entity)). Datasaur attaches an attribute value to an applied label via right-click → Add attribute and shows it next to the label name and in the tooltip ([span-based how-to](https://docs.datasaur.ai/data-studio-projects/lets-get-labeling/span-based.md)). Both keep the status on the span; a toggle on the slot chip is the same idea in a cheaper form. Datasaur's note that label + attribute are one unit in review conflicts is a reminder to store the status with the span, not beside it.
- **A note field that steals focus must suspend the shortcuts.** Label Studio's hotkey layer switches scope when focus is in `INPUT|TEXTAREA|SELECT` or a contenteditable, so labelling hotkeys do not fire while typing ([Hotkey.ts](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/core/Hotkey.ts)). Argilla uses `Shift+Enter` to enter a text area and `Esc` to leave it ([shortcuts](https://docs.argilla.io/latest/how_to_guides/annotate/#shortcuts)), the same Esc-returns-to-page behaviour the addendum asks for. Prodigy's `text_input` block has `field_autofocus` (default `false`) and is recommended for "leave feedback about a manual NER annotation task" ([text_input](https://prodi.gy/docs/api-interfaces#text_input)). So auto-focus is a deliberate per-field choice; doing it only when a note is required is consistent with all three.
- **Required-only-when-triggered mirrors existing gates.** Label Studio's `Choices required`/`requiredMessage` validates on Submit and opens a modal ([Required.js](https://github.com/HumanSignal/label-studio/blob/develop/web/libs/editor/src/mixins/Required.js)), and Prodigy's `validate_answer` raises an error on submit ([custom recipes](https://prodi.gy/docs/custom-recipes#validate_answer)). An inline message under the note ("Add a note: what is unclear?") is lighter than either modal; [INFERENCE] keep it inline and keep the focus in the field.
- **Placement.** Slot toggle on the chip (printed key `c`, shown only for slots that declare statuses) and the note directly under the slots keeps one reading order: text → slots → note → status buttons. [INFERENCE] Show the saved note as one truncated line in the state chip area, with the full text on hover.
